## 数据库与发布顺序

全新空库使用 [MySQL 8 建库基线](../FitBitePal-Backend/src/main/resources/db/baseline/mysql8.sql)。Compose 在数据库卷首次初始化时执行它，创建 13 张业务表。上线前的生产配置启动测试用 Hibernate 核对实体映射、索引及空库状态。已有数据卷走下面的升级路径。

从已经完成 V7 的库升级时，应先备份并排空旧实例的姿态会话，再在数据库执行 [V8](../FitBitePal-Backend/src/main/resources/db/migration/V8__pose_session_lifecycle.sql) 和 [V9](../FitBitePal-Backend/src/main/resources/db/migration/V9__daily_lookup_indexes.sql)，最后启动采用 `prod` 配置的新版本。V8 增加可空字段，旧行继续作为已保存历史处理。V9 建立非唯一索引，保留历史重复记录。生产配置使用 Hibernate `validate`。仓库历史迁移文件由部署流程执行。

Redis 应用缓存切换为 `fitbite:v2:` 前缀。升级后缓存从 MySQL 重新填充，旧键按其 TTL 自然到期。验证码沿用独立键和有效期。

## 邮件与移动端验证

本机 SMTP 为 `127.0.0.1:1025`，收件界面为 [Mailpit](http://127.0.0.1:8025)。本地配置的所有信件均留在本机。外部收件人的投递取决于部署方的发信域及服务商授权。旧版本曾提交过 SMTP 凭据，仓库内容变更无法撤销历史凭据，旧授权码需在原服务商处撤销。[邮件配置](../FitBitePal-Backend/EMAIL_CONFIGURATION.md)

后端工作流使用 MySQL、Redis 和 Mailpit，移动端工作流根据锁文件安装依赖，执行单位测试并导出 Android 和 iOS 的 Expo/Hermes 资源包。[后端 CI](../.github/workflows/backend.yml) · [移动端 CI](../.github/workflows/mobile.yml)

## 本轮执行结果

- Maven 从空构建目录完成打包。40 项后端测试全部通过，失败、错误和跳过数均为零。运行环境包含 MySQL 8.0.44、Redis 7.2.7 和 Mailpit 1.27.4；按各测试职责使用真实服务或隔离替身。
- 独立启动可执行 JAR，使用空库基线和实际 Redis。健康检查、注册、登录、资料保存、两次读取训练与饮食计划、当日打卡、重复打卡、读取更新后的体重均通过。
- 移动端按照锁文件安装依赖，3 项单位回归测试全部通过。Android 和 iOS 均完成生产模式的 Hermes 资源导出。
